# Binance Pay（个人账户）

支付方式 `binance`，币种 USDT，使用官方 `/sapi/v1/pay/transactions` 只读签名接口。无需商户账户。此功能不会主动扣款，也不提供退款或提现。

## 配置

在服务进程或 Docker 容器中设置环境变量，重启服务：

```sh
BINANCE_UID=12345678
BINANCE_API_KEY=your_read_only_api_key
BINANCE_API_SECRET=your_api_secret
```

UID 必须是该 API 密钥所属收款账户的 Binance 用户 ID，不是旧版 Pay ID。密钥只需读取权限，不要开启交易或提现权限，建议绑定服务器 IP。不要把真实密钥提交到 Git。服务器时钟需准确，部署地区需能访问 Binance API，账户需获准使用该接口。

收银台选择 **official** 模板。配置完整后，USDT 的网络选项自动出现 Binance Pay，无需添加链上钱包。后台钱包新增也支持 `binance` 类型及数字 UID，但实际收款始终采用上述服务环境的 UID；当前仅支持一个收款账户。

## 付款

1. 用户在集成收银台选择 USDT → Binance Pay。
2. 打开币安 App → Pay → 转账，输入收银台显示的 Binance UID，核对收款人。
3. 转账**完整且精确的 USDT 金额**（例如 `10.01`），不要改成 `10`，不要使用链上提现。
4. 后台每分钟读取流水，核验后自动更新订单并触发原有商户通知。付款人无需输入自己的 UID，也无需上传截图。

兼容 API：原有创建订单参数 `trade_type=binance`；易支付 `type=binance`。使用原有签名、金额、汇率及回调约定。集成收银台更新付款方式使用 `currency=USDT, network=binance`。

## 匹配与恢复

只接受收款 UID 一致的正数 USDT `C2C` / `PAY` 流水，精确比较金额，并要求流水时间位于订单创建与过期时间之间。退款、红包、支出、其他币种不参与匹配。固定金额订单沿用原有金额递增分配机制，Binance 不采用全局的模糊金额匹配，也不支持零金额或地址独占订单。

流水交易 ID 和本地订单 ID 均持久化唯一约束，并在同一数据库事务内结算，防止重复通知或跨订单重放。已过期但在配置回溯范围内的订单可补查有效期内到账；过期后付款需要人工处理。重启后从尚未结算订单重新查询，无需内存游标。

查询满 100 条时拆分时间区间，避免截断遗漏。接口限频、不可访问或返回异常时保留订单等待下一轮；失败日志不包含密钥或签名 URL。该接口权重较高（官方目前标注 UID 权重 3000），高流水情况下区间拆分可能触发限频。

个人收款流水通常只提供付款人姓名，不能通过输入付款人 UID 验证身份。不得将此字段当作付款凭证。尚未使用真实账户和真实资金进行端到端验证，上线前需以小额订单核对到账及商户回调。

官方接口文档：https://developers.binance.info/en/docs/catalog/investment-and-services-pay/api/rest-api/
