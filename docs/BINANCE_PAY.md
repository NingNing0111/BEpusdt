# Binance Pay 个人 UID 收款

支付方式（trade_type / 易支付 type）：`binance`，币种：USDT，收银台 network：`binance`。

## 配置

1. 在收款币安账号创建可以查询 Pay 转账历史的 API Key，仅授予读取权限，不需要交易或提现权限。建议配置服务器 IP 白名单。
2. 配置服务端环境变量 `BINANCE_API_KEY`、`BINANCE_API_SECRET` 并重启服务。Docker 部署需要将变量传入容器；密钥不要填写在钱包备注中。
3. 后台「钱包」新增交易类型 `USDT・Binance Pay`，地址填写此 API Key 对应收款账号的 **币安用户 UID**。这里使用 UID，不是 Pay ID，也不是链上地址。一个服务实例对应一个币安账号。
4. 商户指定 `trade_type=binance`（易支付为 `type=binance`），或让用户在内置收银台选择 USDT → Binance Pay。原签名、订单查询、异步回调和回调重试协议继续使用。

## 买家使用

在币安 App 内选择转账给币安用户，输入收银台显示的收款 UID，选择 USDT，输入页面显示的完整金额。例如商品是 10 USDT，并发订单可能显示 **10.01 USDT**，必须支付 10.01。手续费不能从到账金额内扣。不要使用链上提币。

系统每 30 秒查询 `/sapi/v1/pay/transactions`，仅接受 `C2C` 类型、USDT、正数收入、匹配收款 UID、金额完全一致且发生在订单有效期内的交易。该接口中正数表示收入；不会将退款、红包、支出视为付款。付款成功后沿用现有回调机制；交易号记录为 `binance:<transactionId>`，无链上浏览器链接。

收款端历史通常只给付款人姓名，不提供付款 UID，因此不要求买家提交自己的 UID，按收款 UID + 唯一尾数金额 + 时间窗口匹配。Binance 始终精确匹配，不受全局宽松匹配设置影响，不支持零金额地址独占订单。

## 自动核验与恢复

- 每轮覆盖仍在回溯窗口内的待支付/已过期订单，付款时间必须处于原订单有效期内。重启和临时 API 故障后可补查；超过配置的回溯窗口需人工处理。
- 满 100 条时按毫秒区间递归拆分查询，避免单页上限漏单。同一毫秒仍达到上限时停止本轮，记录告警，不在数据不完整时入账。
- 新增收款凭据表，交易 ID 和订单 ID 分别唯一；凭据与成功状态在一个数据库事务中写入。重复轮询和并发处理不能重复结算；即使删除订单仍保留凭据。已成功订单使用原有回调重试任务恢复通知。
- API 超时、非 200、业务错误和无效响应不确认付款；日志不输出签名请求 URL 或密钥。保持服务器时间同步。
- 未设置 API 凭据时轮询关闭。上线前先用小额真实转账确认该账号/API Key/地区可查询个人 C2C 收款；本项目测试使用模拟 API，不代表币安账号权限已经验证。

API 依据：https://developers.binance.com/docs/pay/rest-api 。此功能使用个人 Pay 历史查询，不使用商户 Binance Pay 下单与 webhook，也不生成未经币安认可的付款二维码。两套内置收银台展示 UID 与转账说明。
